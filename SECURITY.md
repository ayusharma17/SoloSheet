# Security policy

## Supported version

Security fixes are made on the latest commit of `main`. This project does not
currently maintain supported release branches.

## Reporting a vulnerability

Please use GitHub's **Report a vulnerability** flow on the repository Security
tab so the report and any proof of concept remain private. Do not open a public
issue for an unpatched vulnerability and do not include credentials, student
documents, signed URLs, payment data, or other personal data in a report.

Include the affected route or component, impact, reproduction steps, and any
suggested mitigation. You should receive an acknowledgement within seven days.
Please allow a reasonable remediation window before public disclosure.

## Scope and safe testing

Good-faith testing is welcome against your own local deployment and accounts.
Do not access other users' data, disrupt a hosted service, perform denial-of-
service testing, or send real lecture material to third-party providers without
authorization. The repository's automated tests are designed to run offline or
against a disposable local database.
